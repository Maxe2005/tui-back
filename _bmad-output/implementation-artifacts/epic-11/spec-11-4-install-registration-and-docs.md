## Intent

**Problem:** A colleague who installs `tui-back` has no pointer to the MCP server and must write the client config by hand; the README says nothing about the MCP tools, their safety classes or the authorization behaviour.

**Approach:** `install` prints the exact registration command and JSON config (never edits any client config), `--uninstall` mentions removing it, and `README.md` gains an MCP section generated by hand from the real tool table.

## Boundaries & Constraints

**Always:** Install writes only what 10.3 already writes (npm global, `~/.bashrc` block, completion file). Registration text is data in the result (JSON line when piped, lines in human text). The README tool list must match `TOOL_DEFINITIONS` exactly (names and safety class). English everywhere.

**Ask First:** Any new write to a file outside what 10.3 already touches.

**Never:** Editing `~/.claude.json`, `.mcp.json` or any client config. Running `claude mcp add` from the installer. Changing the install error codes or the existing result fields.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Install ok | `tui-back install` | Existing result plus `mcp: { command: "claude mcp add tui-back -- tui-back mcp", config: {mcpServers:{"tui-back":{command:"tui-back",args:["mcp"]}}} }`; human text prints both, labelled "not applied" | N/A |
| Install fails | old Node / npm error / corrupt rc | Same error as today; no registration text | unchanged |
| Uninstall | `tui-back install --uninstall` | Existing result plus `mcpNote` naming `claude mcp remove tui-back` and "remove the `tui-back` entry from other clients' config"; human text prints it | N/A |
